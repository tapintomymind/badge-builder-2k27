# `src/data/` — the dataset

Read-only at runtime. Consumed as a bundled module import, never via `fs` or any
absolute path.

The shipped dataset is **generated**, not hand-edited. The checked-in source text
is the single place a number may be typed, and a test asserts that regenerating
from that source reproduces the shipped dataset byte-for-byte. This makes a data
refresh a one-file edit with a reviewable diff.

Note the honest limit of that guarantee: the generator RELOCATES transcription
risk into its abbreviation map rather than removing it. The two controls that
close it — an alias-map bijection test and a 13-badge spot-check against
literals hand-transcribed from the sealed requirements doc — are ship gates in
the test suite (`tests/alias-bijection.test.ts`, `tests/spot-check.test.ts`).

**Never invent data.** An unknown value stays unknown (`null`) — it is never
guessed, rounded, or filled in from intuition.

## Files

- `badges.source.txt` — the sealed seed's 53-badge listing, VERBATIM. Beware:
  U+2014 `—` is both the name/attr separator and the null-threshold token,
  while heights use U+2013 `–`. Do not "clean up" the separators.
- `badges.enrichment.source.txt` — **the SECOND source file (F4).** 53
  pipe-delimited rows, `Name | NEW? | description`, carrying the official
  page's one-line ability summaries and its NEW flags. Row order does not
  matter (the join is BY NAME); the checked-in file keeps the capture doc's
  category order for reviewability. The NEW field is the exact literal `NEW`
  or empty — nothing else.

  **This is a second file, never an edit to `badges.source.txt`.** That file's
  contract is *the sealed seed's 53-badge listing, VERBATIM*, and a
  byte-equality test rides on it; a description typed into it would break the
  contract the whole pipeline rests on.

  **Join contract, throw-on-mismatch:** `generate(source, enrichment)` parses
  the roster FIRST (so an unknown attribute label throws ITS OWN error, never
  a join error), then the enrichment, then joins by name. It THROWS — never
  defaults — on a field count other than 3, a NEW token that is neither `NEW`
  nor empty, an empty description, an empty name, a duplicate name, a name in
  the enrichment that is not in the roster, a roster name absent from the
  enrichment, and a row-count mismatch. A name disagreement means the two
  SOURCES disagree: **ask, never adjust either file.**

  **Provenance:** the official 2K MyPlayer Builder page,
  <https://nba.2k.com/2k27/features/myplayer-builder/>, accessed 2026-08-26.
  The URL lives here and in the generator's provenance comment only — the
  shipped `source` string in `badges.json` names the page and the access date,
  not the link. The descriptions in the enrichment file are the capture doc's
  paraphrases, transcribed character-for-character; they are **not**
  re-paraphrased, because re-paraphrasing is both a copyright regression and
  an invention.

- `badges.json` — generated by `npm run generate:badges` from BOTH source
  files. Never edit by hand; a byte-equality test enforces this. Carries
  provenance (`dataVersion`, `gameVersion: null` until published,
  `confidence`).
