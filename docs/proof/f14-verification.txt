1. TWO DEFECTS FOUND IN THE BROWSER THAT NO AMOUNT OF PAPER WOULD HAVE CAUGHT
--------------------------------------------------------------------------------
(a) scroll-padding-top and scroll-margin-top ADD.

  design.md §4.3 derives `.grid-section { scroll-margin-top: 48 }` and §6.2
  derives `.col-right { scroll-padding-top: 107 }` INDEPENDENTLY. They are not
  independent: the scrollport's padding and the target's margin sum.

    shipped for one hour   120 reserve + 44 margin  ->  section landed 164.1
                           down, with 120px of the PREVIOUS category showing
                           under the nav — the exact hole §4.3 set out to avoid,
                           arriving from the other direction.

  FIX: a `--scroll-reserve` custom property, 0 on the document scroller and
  `var(--sticky-stack-h)` on `.col-right` under the shell, subtracted by every
  scroll-margin. The LANDING POSITION is then one number at every breakpoint
  and only one of the two terms ever moves. Under the shell `.grid-section`'s
  computed scroll-margin-top is −76px, which is correct and looks like a typo,
  which is why assertion 11 asserts the landing rather than the declaration.

(b) `html, body { overflow: hidden }` does NOT stop the viewport scrolling.

  The root element's overflow PROPAGATES to the viewport and the root's own
  used overflow becomes `visible`, so the viewport remained a scroll container
  with an 8584px scrolling area even though body was 900 and clipping. Hidden
  stops the USER; it does not stop the browser, and scroll-an-element-into-view
  walks every scrollable ancestor.

    MEASURED, shell on at 1280x900, clicking the Summary jump chip:
      documentElement.scrollHeight  8584   (clientHeight 900)
      documentElement.scrollTop      365   after the click
      .app-header top               −365   header and F13 strip off screen

  That is SH-2 — the frame the whole slice exists to make possible — failing.
  Three candidate fixes were measured:

      html { overflow: clip }            scrollArea 8584, top 365   FAILS
      html { height/max-height: 100dvh } scrollArea 8584, top 365   FAILS
      .app-shell { position: fixed }     scrollArea  900, top   0   PASSES

  FIX: the shell root is taken out of flow (`position: fixed; top/left/right: 0`
  with the explicit vh/dvh height pair — never `inset: 0`, which would infer the
  height from a viewport the pair exists to disambiguate). The @supports
  fallback restores `position: static`.
