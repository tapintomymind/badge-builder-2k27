2. NAME_MIN_CONTENT — MEASURED, THEN RE-PINNED ON RATIFICATION
--------------------------------------------------------------------------------
Chrome/151.0.7922.174, --headless=new, driven over CDP, viewport 1280,
deviceScaleFactor 1. A width:min-content probe carrying the class a real badge
name carries, appended INSIDE a live .synergy-board__button so it inherits the
cell's own font stack and --text-xs size.

  "Unpluckable"            70.156   <- binding (11 chars, no break)
  "Interceptor"            62.563       (11 chars, tied on count)
  "High-Flying Denier"     36.969       (the hyphen breaks it early)

RATIFIED: PIN AT THE CEILING, 71. Take-the-larger is this project's
established discipline for a measured constant — F5.4 kept NUMERIC_H at 27
over a measured 26 for the same reason: a floor derived from a constant known
to be LOW is optimistic, and an optimistic floor is not a floor.

  THE RE-DERIVATION, in full:

    NAME_MIN_CONTENT   68  ->  71     ceil(70.156)
    CELL_FLOOR         86  ->  89     71 + 2 x --space-2 + 2 x 1px border
    8-wide floor      829  -> 853     8 x 89 + 72 + 7 x 8 + 13
    4-wide floor      440  -> 452     4 x 89 + 72 + 3 x 8
    binding margin
      at 1280/s=17    +7.00 -> +4.00  cellW 93.00 against CELL_FLOOR 89

  WHAT IT FIXES, and it is a real defect rather than bookkeeping. At the old
  floor the board went eight-wide from board box 829, where a cell offers
  68.00px of content against the 70.156 the longest badge name wants. The
  board entered a ~24px band in which its own longest name did not fit: a
  number that was defensible, wrong, and green. At 853 the cell offers
  exactly 71.00 and the word fits AT the floor by construction — asserted
  directly, as `contentAtFloor(SPLIT_THRESHOLD) === NAME_MIN_CONTENT`, with
  the old 829 kept as the canary that fails the property.

  WHAT IT DOES NOT CHANGE. No coverage width moved. 1280 (box 902 at s=0, 885
  at s=17) and 1440 (1062) were always far clear of both floors; 768 (702) is
  four-wide under both; 390 (332) is two-wide under both. The behaviour delta
  is confined to board box 829..852, which no coverage width occupies.

  THE STYLESHEET'S NUMBER IS STILL THE DERIVED DEMAND, not a transcription.
  Both thresholds are written in @container RANGE syntax — `(width < 853px)`
  and `(width < 452px)` — so the figure in the CSS is the derivation's own
  output with no max-width off-by-one in between, and
  tests/layout-arithmetic.test.ts re-derives both from PARSED values
  (ROW_LABEL_W off the track list, CELL_GAP off column-gap, BAND_DIVIDER off
  the seam track plus one gutter, CELL_PAD and CELL_BORDER off the button).
  Nothing in the block is a pasted threshold. That property is why the
  original error was catchable at all, and it survives the re-pin: the 4-wide
  floor moved 440 -> 452 by itself, because it is the same rule one step down.

  Assertion "1b" was FLIPPED from recording a divergence to pinning the
  ratified value: it now asserts NAME_MIN_CONTENT === ceil(NAME_MIN_MEASURED),

9. THE ONE DEFECT FOUND AND FIXED DURING THE CUT
--------------------------------------------------------------------------------
The narrow arrangements' band placement was written as `.synergy-board__band
{ grid-column: 1 / -1 }` — specificity (0,1,0) — against wide placements
written as `.synergy-board__band[data-band="..."]` at (0,2,0). The bare
selector LOST, the Permanent band kept columns 7/11, and the five-track
template grew five implicit tracks it never sized. Measured before the fix:
cellW 88.97 at 768 against a 151.50 demand, and 2.00 at 390.

Caught by measuring rather than by looking, and worth recording because a
green suite said nothing about it: no jsdom test can see a collapsed grid
track, and the arrangement is correct in the DOM at every width.

11. HOW THE BROWSER PROOF WAS SERVED
--------------------------------------------------------------------------------
NOT on the pinned 5173 origin. The dispatch forbids starting a dev server
there because every worktree shares that origin's localStorage and stale code
could strip fields from the operator's real saved builds. Served on
http://localhost:5111 instead (`npx vite --port 5111 --strictPort`), which is
a DIFFERENT origin and therefore a different localStorage store — the same
isolation F5.4 used at 5199/5201. The fixture was injected with
Page.addScriptToEvaluateOnNewDocument so it lands before any page script; the
operator's own 5173 store was never opened, read or written.
