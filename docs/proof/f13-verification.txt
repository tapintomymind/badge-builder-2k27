banner "would not render" twice. Both operations are done from a neutral page
in the same file:// storage bucket instead. Every state below was re-taken
after the fix.

Below 768 that makes it a FOURTH CHILD of `.section__body` — which is
`display: flex; flex-direction: column; gap: var(--space-3)`. So the notice's
arrival buys an extra FLEX GAP it never used to cost, and the clamp state at
390 measured 3396.86 against pre-F13's 3384.86: EXACTLY +12.

THE FIRST FIX WAS AIMED AT THE WRONG 12PX. `.attr-group`'s bottom margin is
also --space-3 and also sits between those two elements, so it looked like
the cause. Zeroing it and re-declaring it below the notice changed the number
by ZERO — because it was never the cause. Recorded because it is the third
time on this project a plausible diagnosis has been overturned by
measurement, and because the two 12s are genuinely easy to confuse.

  pre-F13   fieldset 131.56 (notice inside) + 12 margin        = 143.56
  naive     fieldset  93.19 + 12 GAP + notice 38.38 + 12       = 155.57
  shipped   fieldset  93.19 + 12 gap - 12 + notice 38.38 + 12  = 143.57

Three rules, all scoped to `.build-panel` so the strip (which lays the notice
out as a grid row and never had a flex gap) is untouched: zero the fieldset's
margin while the notice follows it, cancel the introduced gap with a negative
top margin, re-declare --space-3 below the notice where pre-F13 it was.
